## 1. 项目整体说明

### 1.1 项目要解决什么问题

本项目是一套面向比赛场景的**多模态客服智能体**，完整链路如下：

```
用户输入（文本 + 图片）
    → 理解 → 分解 → 路由 → 检索 → 生成 → 验证 → 回答
```

要解决的四个核心问题：

1. **多模态理解**: 用户问题可能是纯文本、附带图片、或图片加文字。需要解析图片内容、提取产品线索、判断证据类型（service_like / manual_like / mixed_like）。
2. **精准检索**: 产品手册知识和客服政策知识分开管理。客服类问题（退款、投诉、发票）和产品使用类问题（说明书、操作步骤）需要路由到不同知识源。
3. **多轮对话**: 同一 `session_id` 下多轮问答需要保持上下文一致性。
4. **幻觉抑制**: 禁止编造手册内容、政策细节或图片编号；无法确认的内容必须保守表达；小模型修正器负责在生成后验证并修正不一致的答案。

### 1.2 整体架构由哪些模块组成

```
src/api.py                          # FastAPI HTTP 入口
    │
    ├── ConversationManager          # 多 session 状态管理
    │
    └── ResponseGenerator           # 主编排器
            │
            ├── MultimodalUnderstanding   # 图片+文本结构化理解（VLM/规则/Hybrid 三后端）
            └── DualRouteRetriever       # 双路检索编排
                    ├── RouteClassifier  (LLM API / 规则 / ONNX 三后端)
                    └── RAGEngine        (Infini Embedding + FAISS + Reranker)

辅助工具:
    ├── ChainOfThoughtReasoner     # 幻觉检测 + CoT 推理
    └── LLMSpellCorrector           # 拼写纠错
```

### 1.3 各模块之间的关系

| 上游模块 | 依赖下游 | 说明 |
|---------|---------|------|
| `api.py` | `ResponseGenerator` | 只做 HTTP 协议封装和响应格式映射，不含业务逻辑 |
| `ResponseGenerator` | `MultimodalUnderstanding` | 可选，失败不阻断 |
| `ResponseGenerator` | `ResponseGenerator` | 问题分解已内联（CoT 由 `ChainOfThoughtReasoner` 处理） |
| `ResponseGenerator` | `DualRouteRetriever` | 所有检索必经之路 |
| `ResponseGenerator` | `LLMHallucinationVerifier` | 可选，默认启用，失败不阻断 |
| `DualRouteRetriever` | `RAGEngine` | Infini Embedding + FAISS 向量检索 |
| `DualRouteRetriever` | `RouteClassifier` | LLM API 分类，可降级规则路由 |
| `DualRouteRetriever` | `LLMSpellCorrector` | query 纠错，失败不阻断 |

### 1.4 外部 API 服务依赖

| 服务 | 模型 | 用途 |
|------|------|------|
| Infini AI（默认） | `deepseek-v4-pro` | LLM 生成、路由分类、幻觉验证、拼写纠错 |
| Infini AI（默认） | `qwen-vl-plus` | 视觉理解（图片 Caption / 结构化理解） |
| Infini AI（默认） | `bge-m3` | 文本向量化 |
| Infini AI（默认） | `gte-reranker-v2-m3` | 重排序 |
| 本地模型（可选） | `qwen2.5-0.5b-instruct` | 小模型验证/纠错（CPU 可运行） |
| 本地模型（可选） | `qwen2.5-1.5b-instruct` | 小模型修正（CPU 可运行） |

**配置来源**: 所有 API Key、模型 ID、Base URL 统一从 `.env` 读取（`INFINI_API_KEY` / `INFINI_MODEL_ID` / `INFINI_BASE_URL`）。
**本地模型路径**: 默认存放在 `D:\models\`（避免占用系统盘）。

## 3. 整体运行流程图

### 3.1 在线主链路流程

```
HTTP POST /chat { question, images?, session_id? }
        │
        ▼
api.py chat()                         ← HTTP 入口
        │
        ├─→ verify_token() Bearer 认证
        ├─→ ChatRequest 参数校验
        ├─→ ConversationManager 获取或创建 session
        ├─→ 添加用户消息到历史
        ├─→ response_generator.generate()
        │       │
        │       ├─→ Step 1: MultimodalUnderstanding.analyze()
        │       │       │
        │       │       └─→ 根据 multimodal_backend 选择后端
        │       │               ├─→ "rule"   → 纯规则链
        │       │               ├─→ "vlm"    → VLM 结构化输出
        │       │               └─→ "hybrid"  → VLM 优先 + 规则补全
        │       │
        │       ├─→ 问题分解 + CoT 推理（内联在 response_generator.py）
        │       │       ├─→ _split_simple_questions()  ← 规则版拆分
        │       │       └─→ cot_reasoner.decompose_question()  ← CoT 推理版
        │       │
        │       ├─→ Step 3-4: 对每个子问题独立执行
        │       │       │
        │       │       ├─→ RouteClassifier.predict()    ← LLM API 后端（默认）
        │       │       └─→ DualRouteRetriever.retrieve()
        │       │               ├─→ service → 词项检索（无向量索引）
        │       │               ├─→ manual  → FAISS + 多维评分重排
        │       │               └─→ mixed    → 两路合并
        │       │
        │       ├─→ 回答生成 + 拼接
        │       ├─→ ChainOfThoughtReasoner 幻觉检测/修正
        │       └─→ 覆盖率检查 + 图片关联
        │
        ├─→ 添加助手回复到历史
        └─→ 返回 StandardResponse { answer, session_id, timestamp }
```

  - `data:image/jpeg;base64,`
  - `data:image/webp;base64,`
- `stream=true` 当前仅作为**前向兼容字段**保留，服务端仍返回同步完整 JSON，不输出 SSE/分块流

### 4.2 多轮对话管理

```
会话上下文（ConversationContext）
    │
    ├── session_id: 唯一标识
    ├── messages: Message[]  (role, content, images, timestamp)
    ├── created_at / last_active
    ├── user_info

        │

    │   └─ 返回新 session_id
        │

    │   ├─ 追加消息到 messages[]

**部署说明**:

- Bearer Token 建议通过环境变量注入，并在网关层配合限流、访问审计和 TLS 终止

### 4.3 多模态理解

**`src/modules/multimodal_understanding.py` - MultimodalUnderstanding（~1538 行）**

多模态理解模块负责解析用户输入的文本和图片，识别产品线索和证据类型。
支持三种后端模式，由配置项 `multimodal_backend` 控制：

| 配置值 | 含义 | 说明 |
|-------|------|------|
| `rule` | 纯规则链 | 离线运行，无需 VLM API，置信度固定 |
| `vlm` | 纯 VLM | 调用视觉大模型做结构化输出 |
| `hybrid`（默认） | VLM 优先 + 规则补全 | VLM 不可用时自动回退规则 |

#### 4.3.1 主入口：`analyze()`

```
输入: question + images + conversation_history
        │
        ├─→ multimodal_backend == "vlm"  → _analyze_via_vlm()
        ├─→ multimodal_backend == "rule"  → _analyze_via_rule()
        └─→ multimodal_backend == "hybrid" → _analyze_hybrid()
                │
                ├─→ VLM 成功 → _merge_with_rule() → VLM 结果 + 规则补全
                └─→ VLM 失败 → _analyze_via_rule() 回退规则链
```

#### 4.3.2 VLM 路径：`_analyze_via_vlm()`

```
输入: question + images + history
        │
        ├─→ _ensure_vlm_initialized()  ← VLMUnderstandingEngine 单例
        ├─→ _parse_conversation_context()  ← 从历史提取最近3轮摘要
        ├─→ _vlm_engine.understand()  ← 视觉大模型结构化理解
        │       ├─→ 调用视觉大模型 API（Qwen-VL / GPT-4V）
        │       ├─→ 返回 MultimodalUnderstandingResult
        │       └─→ 失败 → 返回 None
        │
        ├─→ VLM 成功 → 返回结果（notes 标记 backend=vlm, stage=full）
        └─→ VLM 失败 → 回退 _analyze_via_rule()（notes 标记 vlm_fallback=True）
```

**VLM 输出字段**: `normalized_query` / `language` / `product_candidates` / `image_tags` / `visual_intents` / `evidence_type` / `confidence` / `notes` / `referenced_previous_object` / `requires_history_resolution`

#### 4.3.3 规则路径：`_analyze_via_rule()`

纯规则链理解，迁移自原有逻辑：

```
输入: question + images + history
        │
        ├─→ QueryProcessor.normalize_query_for_retrieval()  ← 归一化
        ├─→ _extract_image_tags()  ← 图片 caption + 标签抽取
        ├─→ _resolve_history_reference()  ← 多轮引用检测（"刚才"、"上面"等）
        ├─→ _infer_product_candidates()  ← 产品名推断
        ├─→ _infer_visual_intents()  ← 视觉意图推断
        ├─→ _score_evidence_type()  ← 多信号打分
        └─→ _infer_evidence_type()  ← 最终证据类型判定
```

**图片标签抽取**（`_extract_image_tags()`）：

采用两层结构：

1. **Caption 层**: 调用 `ImageParser.describe_image()`
   - 优先通过视觉大模型 API 生成描述
   - 无 VLM 时 fallback 为规则兜底（仅根据宽高比返回通用描述）
   - 支持评测专用 mock caption（`__mock_caption__:` 前缀）

2. **标签抽取层**: `_extract_tags_from_caption()`
   - Step 1: 关键词精确匹配（部件词 / 状态词 / 图示词 / 产品类型）
   - Step 2: 语义相似度匹配（中文术语与产品词典的余弦相似度，SentenceTransformer 单例）
   - Step 3: 规则过滤 + 去重 + 优先级排序

**产品候选推断**（`_infer_product_candidates()`）：

| 数据来源 | 置信度 |
|---------|--------|
| 文本别名精确匹配 | 1.0 |
| 图片标签推断 | 0.7 |
| 历史上下文 | 0.5 |

按分数降序、去重后最多返回 5 个。

**证据类型打分**（`_score_evidence_type()`）：

| 评分维度 | 说明 |
|---------|------|
| `strong_service_hits` | 强客服意图词（退款/退货/发票等） |
| `weak_service_hits` | 弱客服意图词 |
| `strong_manual_hits` | 强手册意图词（说明书/指示灯/按钮等） |
| `weak_manual_hits` | 弱手册意图词 |
| `service_tag_hits` | 图片标签中的客服类标签 |
| `manual_tag_hits` | 图片标签中的手册类标签 |
| `service_visual_hits` | 视觉意图中的客服类意图 |
| `manual_visual_hits` | 视觉意图中的手册类意图 |
| `has_product_candidates` | 有候选产品时加 manual 分 |
| `has_doc_delivery_service` | 说明书补发类服务请求 |
| `has_manual_symptom_phrase` | 症状描述短语（灯闪/不亮等） |
| `has_mixed_connector` | 混合连接词（顺便/另外等） |

**证据类型推断**（`_infer_evidence_type()`）：

| 条件 | 结果 |
|------|------|
| service_score ≥ 0.42 且 manual_score ≥ 0.42 且差距 ≤ 0.18 | `mixed_like` |
| mixed_score ≥ 0.2 且两侧均 ≥ 0.26 | `mixed_like` |
| service_score ≥ manual_score + 0.12 | `service_like` |
| manual_score ≥ service_score + 0.12 | `manual_like` |
| manual_score ≥ 0.28 且有候选产品 | `manual_like` |
| 两侧均 < 0.2 | `unknown` |

#### 4.3.4 Hybrid 融合路径：`_analyze_hybrid()`

```
输入: question + images + history
        │
        ├─→ VLM 优先 → _vlm_engine.understand()
        ├─→ hybrid_stage 灰度配置
        │       ├─→ "observe"  ← 仅记录 VLM 结果，走规则链（可观测）
        │       ├─→ "product_candidates" ← 合并产品候选
        │       ├─→ "image_tags"        ← 合并产品候选 + 图片标签
        │       ├─→ "evidence_type"      ← 合并产品候选 + 图片标签 + 证据类型
        │       └─→ "full"             ← 全字段采用 VLM
        │
        └─→ VLM 成功 → _merge_with_rule() → 融合结果
                └─→ VLM 失败 → 回退规则链
```

融合规则（`_merge_with_rule()`）：

| 字段 | 融合策略 |
|------|---------|
| `normalized_query` | observe 模式走规则；full 模式用 VLM |
| `product_candidates` | VLM + 规则去重合并，按分数降序 |
| `image_tags` | VLM + 规则去重合并，最多 12 个 |
| `visual_intents` | VLM + 规则去重合并，最多 5 个 |
| `evidence_type` | VLM 为主，违规时用规则 |
| `confidence` | VLM 原值；两侧分歧时降权至 min(VLM, rule, 0.7) |

#### 4.3.5 子组件

| 组件 | 职责 |
|------|------|
| `ImageParser` | Base64 解码 / caption 生成 / 规则兜底 |
| `TextParser` | 旧版文本解析（向后兼容） |
| `VLMUnderstandingEngine` | 视觉大模型结构化理解封装 |
| `QueryProcessor` | 查询归一化（委托自 `text_utils`） |

#### 4.3.6 关键配置项

| 配置项 | 默认值 | 说明 |
|-------|-------|------|
| `multimodal_backend` | `hybrid` | 理解后端模式 |
| `multimodal_hybrid_stage` | `observe` | Hybrid 灰度阶段 |
| `vision_llm_enabled` | `False` | 是否启用视觉大模型 API |
| `vision_llm_model` | `qwen-vl-plus` | 视觉大模型名称 |
| `embedding_device` | `cpu` | 语义编码器设备 |
| `embedding_backend` | `dashscope` | 向量化后端 |

### 4.4 问题分解（内联）

问题分解已内联至 `response_generator.py`，由以下组件协同处理：

**`response_generator.py` - `_split_simple_questions()`**

纯规则拆分，不调用 LLM，按标点快速切分子问题：

```
输入: question
        │
        ├── 按标点分割（?？;；\n）
        │       ├─ 策略1: 问号分割（confidence=0.95）
        │       ├─ 策略2: 分号分割（confidence=0.90）
        │       ├─ 策略3: 换行分割（confidence=0.85）
        │       └─ 策略4: 逗号分割（confidence=0.80）

```

**触发条件**：`_needs_deep_reasoning()` 判断是否需要 CoT 推理：

| 判断条件 | 结果 |
|---------|------|
| 子问题数量 ≥ 3 | 需要 CoT |
| query ≥ 120 字 且 子问题 ≥ 2 | 需要 CoT |
| 存在混合连接词（顺便/另外/同时） | 需要 CoT |
| 其余情况 | 纯规则拆分 |

**`hallucination_controller.py` - `ChainOfThoughtReasoner.decompose_question()`**

LLM 驱动的结构化问题分解：

        └─→ LLM 分解
                ├─→ 构造 decompose_prompt（JSON 格式要求）
                ├─→ 调用 LLM（temperature=0.5）
                ├─→ 解析 JSON 响应
                └─→ JSON 解析失败 → 回退纯规则拆分

输出: {
    "original_question": str,
    "sub_questions": List[str],
    "reasoning_steps": List[str],
    "key_points": List[str],
    "is_complex": bool
}
```

### 4.5 路由分类（service / manual / mixed）

**`src/modules/dual_route_retriever.py` - route_query()**

```
输入: query 文本 + images 图片列表
        │
        ├── Step 1: LLMSpellCorrector.correct() 拼写纠错（可选）
        │   └─ 失败 → 使用原始 query
        │
        ├── Step 2: QueryProcessor.normalize_query_for_retrieval() 归一化
        │
        ├── Step 3: 规则路由评分 (_compute_rule_route_info)
        │   ├─ 意图匹配 → matched_intents[]
        │   ├─ 手册别名检测 → candidate_manuals[]
        │   ├─ service/manual 关键词命中统计
        │   ├─ 示例相似度 (_best_example_score)
        │   ├─ 加权求和 → service_score / manual_score
        │   └─ 分数调节（service_only_hits、意图组合条件）
        │
        ├── Step 4: RouteClassifier.predict() ONNX 分类（可降级）
        │   ├─ Featureizer.build_input_text(): 拼接 query + [HAS_IMAGE] + [IMAGE_TAGS]
        │   ├─ Featureizer.encode(): 512 维特征向量
        │   ├─ ONNX Runtime 推理 → [service_prob, manual_prob, mixed_prob]
        │   └─ 返回 label + confidence + margin(top1-top2)
        │
        └── Step 5: _arbitrate_route() 最终裁决
            ├─ 优先级1: 强规则强制路由 → 直接采纳
            ├─ 优先级2: 高置信分类器（confidence≥0.82 且 margin≥0.25）→ 直接采纳
            ├─ 优先级3: 低置信分类器（confidence<0.46 或 margin<0.08）→ 回退规则
            ├─ 优先级4: 分类器与规则一致 → 采纳分类器
            ├─ 优先级5: 任一方为 mixed → 升为 mixed
            ├─ 优先级6: 规则偏好 service（无手册候选 + 有客服意图）
            ├─ 优先级7: 规则偏好 manual（有手册别名命中）
            └─ 优先级8: 中等置信度 → 采纳分类器

输出: { route, rule_score, classifier_label, classifier_confidence, ... }
```

### 4.6 Manual 检索

**`src/modules/dual_route_retriever.py` - _retrieve_manual()**

```
输入: query
        │
        ├── _detect_manual_candidates(query) 别名匹配
        │   └─ 返回 [(manual_name, alias_score), ...]
        │
        ├── _should_use_local_manual_recall() 判断局部召回
        │   ├─ 别名得分 ≥ 6.0 → 启用
        │   ├─ 仅 1 候选且得分 ≥ 2.0 → 启用

        │
        ├── 未启用局部召回 → 全库 broad recall
        │   └─ rag_engine.retrieve(query, top_k=24)
        │
        └── _rerank_manual_docs() 多维评分重排序
            │
            └─ _score_manual_result() 各维度权重:
                ├─ semantic_score (0.34): 向量相似度

            │
            └─ _apply_diversity_penalty()
                ├─ Top2/Top3 同 section_title → 降 0.05
                └─ 同 section + 相邻 chunk_index → 叠加降 0.03

输出: 重排序后的 top_k 条检索结果
```

### 4.13 路由分类器

**`src/modules/route_classifier.py`** 支持两种后端：

**后端 1: LLM API（默认，`route_classifier_backend = "llm"`）**
```
输入: 归一化 query + images + image_tags + product_candidates
        │
        ├── 构造分类 prompt（service / manual / mixed 三选一）
        ├── 调用 LLM API（Infini deepseek-v4-pro）
        └── 返回 { label, confidence=0.8, available }
```

**后端 2: 规则兜底（`route_classifier_backend = "rule"`）**
```
输入: 归一化 query + images + image_tags + product_candidates
        │
        ├── 提取图片 caption（ImageParser.describe_image）
        ├── _score_evidence_type() → service_score / manual_score / mixed_score
        └── 返回 { label, confidence, margin, available }
```

**后端 3: ONNX 模型（`route_classifier_backend = "onnx"`，可选）**
```
输入: 归一化 query + images + image_tags
        │
        ├── Featureizer.build_input_text() 拼接
        ├── Featureizer.encode() → 512 维向量
        ├── ONNX Runtime 推理 → [service_prob, manual_prob, mixed_prob]
        │
        └── 返回 { label, confidence, margin, available }
            └─ available=False → 主链路降级规则路由
```

| 配置项 | 默认值 | 说明 |

| `route_classifier_enabled` | `True` | 启用分类器 |
| `route_classifier_backend` | `llm` | llm / rule / onnx |
| `route_classifier_high_threshold` | `0.82` | LLM 分类器高置信阈值 |
| `route_classifier_low_threshold` | `0.46` | LLM 分类器低置信阈值 |
| `route_classifier_high_margin` | `0.25` | 分类器 margin 阈值 |
| `route_classifier_low_margin` | `0.08` | 分类器低 margin 阈值 |

## 6. 主链路与辅助链路区分

### 6.1 线上主流程

```
POST /chat
    │
    ▼
api.py chat()                              ← HTTP 入口（行 190）
    │
    ▼
ConversationManager                        ← 会话状态（行 ~150）
    │
    ▼
ResponseGenerator.generate()               ← 主编排（行 119）
    │
    ├─→ MultimodalUnderstanding.analyze()  ← 多模态理解（行 566，可选）
    ├─→ 问题分解 + CoT 推理              ← 内联（行 316/381）
    │       ├─→ _split_simple_questions()  ← 规则版拆分
    │       └─→ cot_reasoner.decompose_question()  ← CoT 推理（可选）
    ├─→ 对每个子问题
    │       ├─→ RouteClassifier.predict()  ← LLM API 分类（默认）
    │       └─→ DualRouteRetriever         ← 双路检索（行 489）
    │               └─→ RAGEngine          ← FAISS + Reranker
    ├─→ 回答生成 + 拼接
    ├─→ ChainOfThoughtReasoner 幻觉检测/修正
    └─→ 覆盖率检查 + 图片关联
```

**主链路特点**:

- 所有代码位于 `src/` 目录
- 入口是 `POST /chat`
- 惰性加载重型依赖（torch、sentence-transformers）
- 任意子模块失败均可降级，不阻断主链
- 目标时延：纯文本 ~20s，多模态 ~30s

### 6.2 离线知识库构建链路

```
scripts/build_knowledge_base.py         ← 手册 JSON → FAISS 索引
scripts/build_dual_route_kb.py          ← 客服知识库构建

```

### 6.3 评测链路
